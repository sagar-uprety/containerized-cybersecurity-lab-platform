The previous firewall administrator used a source-port shortcut to identify reply traffic. Management wants you to verify that a new external connection cannot reach the internal web server.

Your mission:

1. Use the browser terminal to inspect the lab network from the workstation.
2. Identify the firewall and the internal web server it should be protecting.
3. Test whether the internal server is reachable from the external network.
4. Inspect the firewall rules to understand how they work.
5. Determine whether the firewall actually blocks access as intended.
6. Fix any unsafe IPv4 firewall rule you find.
7. Verify that the persistent rules reload and the internal service remains healthy.
8. Run the portal check and record the result.
9. Complete the mandatory feedback form after ending the lab.

Useful paths:

- /lab/config/fw_external_ip.txt (firewall address, on the workstation)
- ~/SITREP.txt

The IPv4 rule file (/etc/iptables/rules.v4) lives on the firewall host, not the
workstation. SSH there as user "firewall" using your own lab password.

Full browser guide:

- /docs/labs/firewall-source-port-bypass/

If the browser terminal is unavailable, use the assigned SSH fallback endpoint.
